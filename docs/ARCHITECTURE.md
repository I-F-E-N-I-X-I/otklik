# Архитектура

- MockLab.Core: Project/Route/Response/Condition — сериализуемые модели; Validator проверяет контракт; ProjectFiles выполняет roundtrip и атомарную запись; Router выбирает маршрут и ответ; OpenApiImporter импортирует ограниченное подмножество.
- MockLab.Server: MockServer управляет Kestrel, создаёт валидированный снимок, читает ограниченное тело, применяет задержку, пишет ответ и ограниченный журнал. Stopwatch измеряет длительность. Очередь ConcurrentQueue; UI уведомляется событием и Dispatcher.BeginInvoke.
- MockLab.Desktop: WPF MainWindow содержит orchestration редактора и файловых диалогов. Доменная логика вынесена в Core. Полный MVVM не реализован: обработчики UI находятся в code-behind, это осознанное упрощение первой версии.
- MockLab.Tests: консольный harness, реальные loopback HTTP тесты без NuGet.

Маршрут сравнивается по сегментам, ordinal case-sensitive. Один завершающий / игнорируется, query отдельно. Параметр занимает целый сегмент. Больше литералов — выше приоритет, при равенстве сохраняется порядок проекта. Дубликаты нормализованного шаблона метода запрещены. 405 содержит Allow.

Rules: первый enabled ответ с непустыми условиями AND, иначе fallback. Header names case-insensitive, значения ordinal. JSON null существует, числа и bool нормализуются. Невалидный JSON даёт несовпадение и причину в журнале.

Sequence: lock защищает выбор и увеличение счётчика, а также reset. Задержка вне lock. Уже принятый шаг не меняется при reset. При остановке Kestrel завершает активные запросы с ограничением ожидания 3 секунды.

Чтобы добавить оператор: расширьте Validator и Router.Check, затем добавьте положительные/отрицательные проверки в harness. Формат проекта остаётся совместимым только в пределах schemaVersion 1.
