# План ручной приёмки Отклик

Чек-лист для повторной ручной приёмки. Выполненные ранее проверки и результаты текущей сборки перечислены в [VERIFICATION.md](VERIFICATION.md); наличие пункта в этом списке не означает, что он пройден.

## Проверка по реальному HTTP

1. Запустить опубликованное приложение и демопроект на 127.0.0.1:3001.
2. curl.exe -i http://127.0.0.1:3001/api/products — проверить статус, Content-Type и JSON.
3. Запросить неизвестный путь — 404; неподдерживаемый метод известного пути — 405.
4. Создать /users/current и /users/{id}; удостовериться, что literal имеет приоритет.
5. Для правила query category=books сравнить запрос с параметром и без него.
6. Для условия заголовка проверить разные регистры его имени.
7. Для JSON body проверить вложенное поле, отсутствие, null и синтаксическую ошибку.
8. Сценарий 500→503→200: четыре последовательных запроса должны дать 500,503,200,200; после reset снова 500.
9. Отправить параллельно медленный и быстрый запрос: быстрый должен завершиться независимо.
10. Предварительный OPTIONS не должен менять номер шага сценария.
11. Остановить сервер и убедиться, что порт освобождён; запустить снова.
12. Попытаться занять уже занятый порт: GUI остаётся доступным, ошибка понятна.

## Пользовательский сценарий

- Создать проект с нуля без редактирования JSON вручную.
- Добавить маршрут, два ответа, условие, fallback и сценарий через интерфейс.
- Исправить ошибочный JSON: поле показывает ошибку до запуска.
- Сохранить, закрыть и открыть: данные сохраняются.
- Изменить запущенный проект: видно, что изменения требуют перезапуска.
- При закрытии с несохранёнными изменениями доступны сохранение, отказ и отмена.
- Выбрать запись журнала: видны запрос, ответ и причина выбора.
- Запустить demo-store и проверить loading, error, retry, empty и success.
- Проверить интерфейс на нормальном и увеличенном масштабе, отсутствие перекрытий и недоступных кнопок.

## Проверка импорта и выпуска

- Поддерживаемый OpenAPI sample импортируется без ручных исправлений.
- Unsupported version и external ref не маскируются успешным полным импортом.
- Сборка запускается из artifacts, а не только через dotnet run.
- Указана зависимость от runtime либо доказано наличие self-contained пакета.
- ZIP действительно содержит запускаемую сборку и инструкции.
- Реальные результаты и оставшиеся ограничения внесены в VERIFICATION.md.
- Публичный сайт и работающая загрузка проверяются отдельно после подготовки пакета.

## Запись результатов

Для каждого результата фиксировать дату, команду/действие, ожидаемое, фактическое и вывод. Не подменять выполнение теста чтением реализации. Непроведённую ручную проверку отмечать как непроведённую.
